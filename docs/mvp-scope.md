# Stage 2: Define the first release 

## Purpose

Define the smallest useful version of the application that solves the problem in the (version 1 in problem-statement.md file). This scope is for the first release; feedback and requests from other user groups can inform later versions.

## Primary user

A student who takes part in projects, courses, events, volunteering, and other learning activities and wants to remember and present that experience later.

## Version 1 outcome

A student can record experiences while they are fresh, find them later when preparing a resume or portfolio, and choose selected experiences to publish on a portfolio page.

## Main user journey

1. Create an account and sign in.
2. Add an experience with a title and category, and optionally add a date and notes.
3. Add project links and, when useful, supporting files or photos.
4. Browse or search saved experiences later.
5. Open the private portfolio editor, select experiences, and write public descriptions.
6. Add profile information and choose which portfolio sections to show.
7. Preview and publish the portfolio at a shareable web address, then view it on a phone or laptop.

## Included in Version 1

- Account sign-up, sign-in, and sign-out.
- Email-based password recovery and account deletion that removes the user's data.
- Create, view, edit, and delete journal entries.
- A flexible entry format with a required title and category; notes and dates are optional.
- Selectable categories for projects, work experience, education, courses or certifications, workshops or events, achievements, volunteering, research or publications, and other experiences.
- Notes, dates, links, and supporting file uploads.
- Browse and search journal entries.
- A responsive web application usable from a phone or laptop browser.
- A portfolio page available to anyone with its shareable web address. Search-engine discovery is out of scope for Version 1.
- An owner-only portfolio editor available from the signed-in journal area. The owner can edit portfolio information, preview it, and publish changes.
- Portfolio sections for About Me, Education, Skills, Projects, Experience, Achievements, Certifications, Workshops & Events, Research & Publications, Resume, Contact, and Social Links. Testimonials and Interests are also supported as optional sections.
- Portfolio profile details and section content can be edited by the owner at any time.
- Empty portfolio sections are hidden from visitors; the page does not display empty-state messages such as “No certifications.”
- Portfolio descriptions are separate from private journal notes. Journal notes and links stay private unless selected public content is deliberately added to the portfolio.
- A file deliberately added to a published portfolio section is public and can be downloaded by visitors. Adding a file to the journal alone never makes it public.

## Out of scope for Version 1

- AI-generated resumes or portfolio content.
- Automatic imports from other apps or platforms.
- Social feeds, followers, or messaging.
- A native iOS or Android application.
- Separate workflows for every experience category.
- Features requested by other user groups until those needs have been investigated.

## Quality goals

- A user can complete the main journey on both phone and laptop browsers.
- One user cannot view or change another user's private entries or files.
- Only the owner can open and edit the portfolio editor; visitors can only view the published portfolio.
- An unpublished portfolio entry or empty section does not appear on the public portfolio.
- Portfolio descriptions and links appear only when deliberately added to published portfolio content.
- An attached file stays private unless the owner deliberately adds that specific file to a published portfolio section.
- The deployed application uses a shareable internet address.
